# ניווט באפליקציה (הסבר לעצמי)

## איך זה עובד בכלל

- `main.jsx` עוטף את כל האפליקציה ב־`BrowserRouter`. זה אומר שכל הכתובת בדפדפן (למשל `/register`) נשארת ב־URL והראוטר בוחר איזו קומפוננטה להציג.
- `App.jsx` מגדיר טבלת מסלולים (`Routes` / `Route`). כל `Route` אומר: אם הנתיב בדיוק X — הצג קומפוננטה Y.

## מה כל נתיב עושה אצלי

| נתיב | מה קורה |
|------|---------|
| `/` | לא מציג דף "בית" — מיד מפנה (`Navigate`) ל־`/register`. זו ברירת המחדל כשנכנסים לאתר. |
| `/register` | טופס הרשמה (תלמידה/מורה). יש קישור לכניסת מורות: `/login`. |
| `/login` | התחברות מורה (ת"ז + סיסמה). אחרי הצלחה → דשבורד. |
| `/end` | מסך סיום אחרי רישום תלמידה (הודעה מה־state). |
| `/dashboard` | דשבורד מורה. בלי טוקן בלוקאל סטורג' → מפנה ל־`/login`. |
| כל דבר אחר (`*`) | מפנה חזרה ל־`/register` כדי שלא יישארו "דפים מתים". |

## שני סוגי מעבר

1. **מעבר בקישור (`<Link to="...">`)** — המשתמשת לוחצת; ה־URL משתנה; הראוטר מרנדר מחדש.
2. **מעבר בקוד (`useNavigate()` + `navigate(...)`)** — אחרי פעולה (רישום / login). `replace: true` אומר להחליף את הרשומה בהיסטוריה כדי שלא "ייחנק" עם כפתור חזרה לטופס ישן.

## מה תיקנתי לעומת לפני

- היה `Navigate` ל־`/login` בלי שיש בכלל Route ל־login — שבור.
- הרישום ניסה ללכת ל־`/thanks` אבל בראוטר היה רק `/end` — לא תואם. עכשיו הכל `/end`.
